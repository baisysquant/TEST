background
The /etc/fstab (File System Table) is a core Linux configuration file that dictates which storage devices, partitions, and network shares are mounted automatically and how they integrate into the system's directory tree.

Every line in the file corresponds to a specific mount point and contains exactly six fields separated by spaces or tabs:
Device: Identifies the storage device
Mount Point: The directory where the device will be accessed 
File System Type: The format of the partition (e.g. ext4 or swap)
Options: Comma-separated mount parameters (e.g., defaults, rw, noexec, or nofail).
Dump: An outdated backup flag. 
Pass: Defines the order in which fsck checks the filesystem for errors at boot (Root should be 1, others 2)

remark
 
GaussDB doesn’t need fstab. 

GaussDB in high-performance mode requires unpartitioned, filesystem-free raw disks. fstab can only mount disks that already have a filesystem, so it can’t be written. 

The database’s cluster management system (CM) automatically takes over, formats, and dynamically mounts these disks at startup, without the need for the OS to get involved. 

During primary/standby switchover, disk ownership needs to shift dynamically. If it’s fixed in fstab, it can prevent smooth unmounting during node failures and even cause double-write data corruption or server boot-ups to hang.
